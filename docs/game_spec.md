# Battleship — Game Specification

This document is the canonical source of game rules and acceptance criteria. The Architect imports it; every builder and reviewer references it.

---

## 1. Players & Match Setup

- Exactly **2 human players** per match, connected from separate browser tabs/devices.
- Players join a shared match via a **6-character room code** (generated by the server when player 1 hosts; player 2 enters it).
- A match has three phases: **Lobby → Placement → Battle → GameOver**.

## 2. Board

- Each player has two 10×10 grids:
  - **Own board** (left): shows their own ships and where the opponent shot.
  - **Tracking board** (right): shows where the player shot, with hit/miss/sunk markers.
- Coordinate system: columns `a–j`, rows `1–10`.

## 3. Fleet

Each player has 5 ships placed on their own board before Battle begins:

| Ship       | Length |
|------------|--------|
| Carrier    | 5      |
| Battleship | 4      |
| Cruiser    | 3      |
| Submarine  | 3      |
| Destroyer  | 2      |

Total occupied cells per player: **17**.

## 4. Placement Phase

- Ships are placed **orthogonally** (horizontal or vertical, no diagonals).
- Ships **must not overlap**.
- Ships **may touch** edge-to-edge (no required gap — keep classic rules simple).
- Ships must stay fully within the 10×10 grid.
- The UI must offer **both** options:
  - **Drag & drop** placement with a `Rotate (R)` action.
  - **Randomize** button — server generates a valid random layout.
- Placement is confirmed via a **Ready** button. Battle starts when both players are Ready.

## 5. Battle Phase

- Players alternate turns. **Host shoots first.**
- On the active player's turn, they click a cell on their tracking board.
- The server:
  - Validates: it's the player's turn, the cell hasn't been shot before, and the match is in `Battle` phase.
  - Computes result: `miss`, `hit`, or `sunk` (hit + that ship has no remaining cells).
  - Updates both players' boards and broadcasts.
- Turn passes to the opponent **regardless** of hit/miss (simple rules variant).
- The active player has **no time limit** in this version (out of scope for the home exercise).

## 6. Visual Indicators

| Result on tracking board | Symbol / class            |
|--------------------------|---------------------------|
| Miss                     | `x` (gray)                |
| Hit                      | `V` on red background     |
| Sunk                     | Whole ship highlighted, animated, with crossed-out `V` per cell |
| Untouched                | Empty cell                |

On the own board, the same conventions apply but ships are always visible to their owner.

## 7. Win Condition

A player wins when **all 17 of the opponent's ship cells are hit**. The server emits a `gameOver` event with the winner's id, both boards are revealed, and a **Play Again** button appears.

## 8. Disconnect Handling (minimum viable)

- If a player disconnects during Placement: the match is dropped, the remaining player is returned to the Lobby with a notice.
- If a player disconnects during Battle: the remaining player wins by forfeit after a 30-second grace window. If the disconnected player reconnects with the same room code + player id within 30 s, the match resumes.

## 9. Out of Scope

- Persistence across server restarts (in-memory state only).
- Accounts, login, persistent profiles.
- Spectators.
- Chat.
- Mobile-specific layouts (responsive desktop layout is enough).

## 10. Acceptance Criteria (used by `requirements-reviewer`)

A build passes AC review only if **all** of the following are demonstrable:

- [ ] **AC-1** Player 1 lands on `/`, sees a "Create room" CTA, and receives a 6-char code.
- [ ] **AC-2** Player 2 enters the code on `/` and joins the same room.
- [ ] **AC-3** Each player can place all 5 ships via drag-and-drop with rotation.
- [ ] **AC-4** Each player can click "Randomize" and receive a valid fleet layout.
- [ ] **AC-5** Placement validates: no overlap, all cells inside the grid.
- [ ] **AC-6** Battle starts only when **both** players click "Ready".
- [ ] **AC-7** Turn indicator clearly shows whose turn it is.
- [ ] **AC-8** Shooting a cell updates **both** clients in under 500 ms.
- [ ] **AC-9** Hits show `V`, misses show `x`, sunk ships are highlighted distinctly.
- [ ] **AC-10** Re-shooting a previously shot cell is rejected by the server.
- [ ] **AC-11** Winning fires a `gameOver` event; both boards reveal.
- [ ] **AC-12** Disconnect mid-battle triggers the 30 s reconnect window.
- [ ] **AC-13** `Play Again` returns both players to a fresh Placement phase in the same room.

The Negative QA agent additionally validates that violations of AC-5, AC-6, AC-7, AC-10 are rejected by the server and do not corrupt state.
